# 0.5 profile publication decision (2026-09-10)

- milestone: `0.5` portable resource profiles
- profile evidence: [`v1-local-half-budget-profile-2026-09-09.md`](v1-local-half-budget-profile-2026-09-09.md)
- current registry baseline: `kafrust 0.4.0` and `kafrust-protocol 0.4.0`
- decision: keep the registry baseline at `0.4.0`; do not publish a `0.5.0` crate pair

The half-budget profile completed all six ordered phases with exact record
reconciliation, zero loss/duplicates/unknown outcomes, drained final gauges,
and no resource-guard breach. The profile is independently reproducible from
the repository, so the `0.5` repository milestone is verified.

The milestone change is limited to campaign scripts, profile configuration,
tests, and evidence documentation. Cargo packages do not include those
repository-level files, and the public Rust API and protocol implementation
are unchanged from the published `0.4.0` pair. Publishing the same package
contents under `0.5.0` would therefore create no new independently consumable
registry boundary. The release policy keeps documentation-only and internal
changes unpublished until they are grouped with a qualified package boundary.

The staged package boundary still passes for the current `0.4.0` pair across
default, TLS, blocking, OTLP, and all-feature external projects. The required
workspace checks also pass: formatting, check, tests, Clippy, documentation,
workflow-version validation, qualification-ledger validation, and
`git diff --check`.

The next registry publication remains a coordinated version pair after a
user-visible or independently consumable change, with a fresh competitor
comparison and protocol-first package verification. The 0.5 profile does not
claim V1-21 high-load fault evidence, V1-22 SLO completion, service-canary
readiness, or `1.0.0` readiness.
